## 1. Що за PDF у нас насправді

Я перевірив обидва файли (`pdffonts`, `pdfimages`, `pdftotext`):

| | 5 клас, Мерзляк (`5-klas-...-1-46.pdf`) | 6 клас, Тарасенкова (`Matematyka_6klas_Tarasenkova.pdf`) |
|---|---|---|
| Сторінок | 46 | 305 |
| Що всередині | Скан-картинка + **невидимий OCR-шар** (шрифт `GlyphLessFont`) | **Лише картинки**, тексту немає взагалі (жодного шрифту) |
| Роздільність скану | ~152 ppi (886×1329 px) | ~150 ppi, деякі сторінки **76 ppi** |
| Звідки "сміття" | Хтось уже прогнав OCR (iLovePDF) з поганою мовною моделлю → `Bech`, `B`, `Ha` замість `весь`, `в`, `на` | `pdftotext` повертає порожнечу |

**Висновок:** обидва — *сканований PDF* (image-only). Старий план казав "зламана таблиця шрифтів" — точніше: це **чужий OCR-шар низької якості**. Довіряти йому не можна, але його можна використати як *другу думку* (див. §4.7).

Важливі наслідки:
1. Рендер у 300 dpi **не додає деталей** — оригінал лише 150 ppi. Апскейл ×2 допомагає Tesseract (він любить висоту літери ~30 px), але це інтерполяція, не нова інформація.
2. Краще **витягувати оригінальну картинку** (`pdfimages -png` / PyMuPDF `extract_image`), а не рендерити сторінку — менше артефактів.
3. Сторінки 76 ppi в Тарасенковій — зона ризику: там OCR буде гіршим, їх треба позначати `low_res=True`.
4. У Тарасенковій є розділ **ВІДПОВІДІ** (стор. ~296+) — це золото для гри: відповіді до вправ за номером.

## 2. Методи розпізнавання PDF (огляд)

### 2.1 Витяг текстового шару (born-digital PDF)
Інструменти: `pdftotext`, `pdfplumber`, `PyMuPDF (fitz)`, `pypdf`.
- ✅ Швидко, точно, є координати символів.
- ❌ Працює лише коли PDF створено з тексту (Word → PDF). **У нас не підходить**, але потрібен як *детектор*: якщо текстовий шар хороший — OCR не потрібен.

### 2.2 Класичний OCR — Tesseract
- Мови: `-l ukr+eng` (eng — для латинських змінних `a`, `x`). Потрібен `ukr.traineddata` (краще з `tessdata_best`).
- `--psm`: `6` (один блок), `4` (колонка змінної висоти), `3` (авто-розмітка), `11` (розкиданий текст — для сітки `1) 2) 3)`).
- **Вивід TSV / hOCR**, а не простий текст: кожне слово має `bbox`, `conf` (впевненість 0–100), `block/par/line`. Без координат неможливо нормально розібрати колонки і відрізнити колонтитул.
- ✅ Безкоштовно, локально, детерміновано.
- ❌ Математику (дроби, степені) ламає; іконки читає як сміття (`зб Задача від Мудрої Сови ох`).

### 2.3 Нейронний OCR
`PaddleOCR`, `EasyOCR`, `docTR`, `Surya`. Кращі на поганих сканах, дають рядки з bbox.
- ❌ Важкі залежності (torch), українська підтримка різна. Варіант "плагіна" — інтерфейс `OcrEngine` дозволяє підключити пізніше.

### 2.4 Аналіз розмітки (layout analysis)
Задача: знайти **зони** — колонтитул, номер сторінки, заголовок, теорія, колонки вправ, рамки ("Задача від Мудрої Сови"), рисунки.
- Простий шлях (наш): евристики по bbox з Tesseract TSV — позиція Y (верх/низ = колонтитул), кластеризація X (колонки), розмір шрифту (висота слова → заголовок).
- OpenCV: пошук рамок/ліній (`findContours`), кольорових плашок, рисунків (великі не-текстові області).
- Готові моделі: `Surya layout`, `Docling`, `Marker` — потужно, але важко контролювати.

### 2.5 OCR математики
`pix2tex (LaTeX-OCR)`, `Texify`, `Nougat`. Розпізнають формулу-картинку в LaTeX.
- Для 6 класу (звичайні дроби `3/4` записані *двоповерхово*) Tesseract безсилий → це зони для vision-LLM або math-OCR.

### 2.6 Vision LLM (Gemini / Claude / GPT)
Даємо картинку сторінки (або вирізану зону) + JSON-схему → отримуємо структуровані дані.
- ✅ Найкраща якість на математиці та структурі.
- ❌ Гроші/квоти, недетермінованість, **галюцинації** (може "дописати" вправу). Тому: лише для зон з низьким `conf` або з математикою, завжди з валідацією і кешем.

### 2.7 Гібрид (наш вибір)
```
Tesseract (усе, безкоштовно)  →  метрики якості  →  Vision LLM (лише проблемні зони)
                                     ↑
                    старий OCR-шар PDF як "друга думка" (лише 5 клас)
```

## 3. Архітектура нового пайплайна

Головний принцип: **парсер не знає про Django**. Він бере PDF і віддає JSON. Окремий імпортер кладе JSON у БД. Так кожен етап тестується окремо, а повторний запуск не потребує повторного OCR.

```
PDF
 │  [0] inspect     — тип PDF, ppi, текстовий шар?             → inspect.json
 │  [1] images      — оригінальні картинки сторінок             → pages/p-005.png
 │  [2] preprocess  — grayscale, deskew, апскейл, бінаризація   → prep/p-005.png
 │  [3] ocr         — Tesseract TSV → Word/Line з bbox+conf     → ocr/p-005.json
 │  [4] layout      — колонтитули, колонки, порядок читання     → layout/p-005.json
 │  [5] normalize   — латиниця→кирилиця, переноси, тире, лапки  → (у пам'яті)
 │  [6] structure   — state machine за профілем підручника      → doc tree
 │  [7] exercises   — номер, складність °/··/*, підпункти 1) 2)
 │  [8] math/figures— формули, вирізання рисунків за bbox
 │  [9] answers     — розділ ВІДПОВІДІ → прив'язка до вправ
 │ [10] validate    — нумерація, дірки, дублікати → report.html
 │ [11] vision      — (опційно) LLM для позначених зон, з кешем
 │ [12] export      — textbook.json (версіонована схема)
 ▼
JSON ──[13] import_textbook (Django, idempotent)──► БД ──► views / API / гра
```

### Ключові типи (орієнтир, не копіюй бездумно)
```python
@dataclass(frozen=True)
class BBox:  x0: int; y0: int; x1: int; y1: int      # пікселі оригінальної картинки

@dataclass
class Word:  text: str; bbox: BBox; conf: float; line_id: int

@dataclass
class Line:  words: list[Word]; bbox: BBox; page: int; zone: str  # "header"|"body"|"footer"|"col1"...
    @property
    def text(self) -> str: ...
    @property
    def conf(self) -> float: ...      # середній/мінімальний conf слів

@dataclass
class Node:  kind: str; number: str|None; title: str; children: list["Node"]
             source: SourceRef            # page, bbox, line range — щоб завжди знайти оригінал
             conf: float; needs_review: bool; data: dict
```
**`SourceRef` у кожній ноді** — найважливіше рішення: будь-яку помилку в грі можна відстежити до пікселів сторінки.

## 4. Особливості саме наших підручників

### 4.1 Мерзляк, 5 клас — маркери блоків
| Блок | Маркер у тексті | `block_type` |
|---|---|---|
| Теорія | текст після заголовка пункту до першого маркера | `theory` |
| Самоперевірка | рядки `1.` `2.` після теорії, до "Розв'язуємо усно" | `self_check` |
| Усні вправи | `Розв'язуємо усно` | `oral_exercise` |
| Вправи | `Вправи` | `exercise` |
| Повторення | `Вправи для повторення` | `review_exercise` |
| Мудра Сова | `Задача від Мудрої Сови` (+сміття від іконки) | `wise_owl` |
| Історія | `Коли зроблено уроки` | `history_aside` |

Складність вправи: `11.°` / `11."` (°→ часто OCR як `"`), `11.··`, `11.*`.

### 4.2 Тарасенкова, 6 клас
- Структура: Розділ → § (35 шт.) → **пункти в тексті §** (їх нема у Змісті — треба знаходити на сторінках).
- Сторінки початку § уже є в `data/tarasenkova_toc_pages.py` (перевірені вручну).
- Маркери блоків **треба дослідити** (план, фаза 9): ймовірно "Дізнайтеся більше", "Пригадайте головне", "Розв'яжіть задачі", рівні складності вправ. Не вигадуй — дивись сторінки.
- Розділ ВІДПОВІДІ: формат `1125. 1) 4; 2) 98; ...` — окремий парсер.

### 4.3 Типові помилки OCR (з реальних файлів)
| Бачимо | Насправді | Як лікувати |
|---|---|---|
| `Bech`, `B`, `Ha`, `cBoei` | весь, в, на, своєї | мапа латиниця→кирилиця для слів, де >50% кирилиці або слово з самих "двійників" |
| `11."` | `11.°` | regex складності після крапки |
| `1)238- 435` | `1) 238 · 435` | знак множення `·` зникає/стає `-`/`.` — позначати `needs_review` |
| `17) 98-34` | `7) 98 · 34` | перевірка послідовності підпунктів (6 → 7, не 17) |
| `натураль-\nних` | натуральних | склеювання переносів |
| `зб ... ох \|` | (іконка) | видалити шум навколо відомих маркерів |
| `3` ↔ `8` | — | перевірка зростання номерів |
| `б)` | `6)` | у контексті підпунктів `б)`→`6)` |

### 4.4 Колонки підпунктів
`1) ... 4) ... 7)` в одному рядку = сітка 3 колонки. Читати треба **по колонках** (1,2,3 потім 4,5,6) — використовуємо X-координати слів `N)`.

### 4.5 Колонтитули
Верхній рядок сторінки: `2. Цифри. Десятковий запис натуральних чисел 7` — це колонтитул + номер сторінки, **не** заголовок. Відрізняємо за Y (верхні ~5% висоти) і за тим, що він повторюється.

### 4.6 Номери сторінок
Номер PDF-сторінки ≠ номер у книзі. Зберігаємо обидва (`pdf_page`, `book_page`).

### 4.7 Старий OCR-шар як друга думка (5 клас)
`pdftotext -bbox` дає слова з координатами. Де наш Tesseract має низький `conf`, а слово старого шару в тому ж bbox — кирилиця і в словнику — можна підставити. Опційно, не першочергово.

## 5. Якість: як міряємо

1. **Golden set**: 5–10 сторінок, які ти вручну транскрибуєш у `tests/fixtures/golden/*.txt`.
2. **CER** (character error rate) = відстань Левенштейна / довжина. Ціль: CER < 3% для тексту.
3. **Структурні метрики**: % вправ з правильним номером, % блоків з правильним типом, кількість дір у нумерації.
4. Кожна зміна препроцесингу/OCR — перезапуск метрик (`python -m education.pdf_pipeline.bench`).

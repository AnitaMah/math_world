# Рішення по фронтенду (DECISIONS)

Формат: дата — рішення, потім «Чому». Нові записи додаються в кінець.
План — `docs/frontend/PLAN.md` (кроки FE-0001…0644).

## 2026-10-07 — гілка `feature/frontend-archipelago` від `feature/pdf-pipeline-v2`, а не від `main`
Чому: `main` відстає на 31 коміт і не має API мапи (`/api/grades/<n>/map/`),
екрана гри та моделей `Player`/`Attempt`/`LessonProgress`, на які спирається
новий фронтенд. Після злиття `feature/pdf-pipeline-v2` у `main` гілка
фронтенду піде за нею без конфліктів.

## 2026-10-07 — межа фронтенд / бекенд
Цей план (і цей чат) — лише:
- `education/templates/` (шаблони),
- `education/static/education/` (CSS, JS, іконки, моки),
- тонкі view-функції й URL, які тільки рендерять шаблони.

Бекенд — окремий чат: моделі, `api.py`, `game.py`, `services.py`,
PDF-пайплайн, імпорт, admin. Межа між ними — JSON-контракт
(`/api/grades/<n>/map/`, `/api/grades/`, `/api/me/`, `/api/play/…`).
Поки бекенд не віддає контракт, фронтенд працює на моках того самого формату.

Чому: два чати працюють паралельно й не чекають один одного; контракт —
єдине місце, де вони мусять домовитися.

## 2026-10-07 — стек: Django-шаблони + ванільний JS (ES-модулі) + CSS
Без React, без збирача (webpack/vite), без npm-залежностей у рантаймі.
Node — лише для інструментів розробки (Playwright-знімки, `node:test`).

Чому: проєкт малий; дизайн — це статичні SVG-острови, кнопки й одна
інтерактивна панель, а не складний стан. Збирач додав би крок, який
легко зламати, і нічого не дав би.
